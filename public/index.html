How this works
1 · Describe

Pick an archetype and answer the questions. Every field has a one-line explanation and a default you should override with what you actually know.

2 · Deterministic maths

Tokens per unit → tokens per month → model cost, with three scenarios (low / base / high) that vary tokens-per-word, retries and cache hit. No LLM guesses a number.

3 · Model, BOM, outcome

The cheapest model above your quality bar (Artificial Analysis), a bill of materials with volumes for the Azure estimator, and cost per valued outcome next to what it costs today. "Open in LLM Task-Fit" hands the workload to the model-ranking app; the BOM markdown goes to the Azure estimator for infra pricing.

Use case

NameiShort working name; appears in the BOM and the architecture document.
ArchetypeiPick the shape of the workload. Each archetype has its own questions, formulas and components — and its own Big-T class (how cost scales).
Outcome unitiThe thing the business gets. Cost is reported per unit of this — not per token.
Where is it counted?iThe system that counts outcomes. No count source, no unit economics.
Quality floor (what counts as a valued outcome)iWhen does an output count? Without a floor you count attempts, and cost per outcome looks better while quality drops.

USD / 1M outputiList price per 1M output tokens. Output is usually 3–5× input price.
